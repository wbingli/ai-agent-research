# Tech Digest — 2026-11-26

**1. 1Password breach exposes the software-delivery attack path**
1Password says a compromised employee GitHub account enabled malicious backend code and theft of some customer account metadata—not vault contents or encryption keys. A concrete reason to tighten repository-to-production controls and watch for targeted recovery-email phishing. [Read](https://1password.com/blog/update-on-nov-2026-security-incident)

**2. Faster AMD inference with a small llama.cpp patch set**
A developer reports generation rising from 35 to 55 tokens/second on an AMD R9700 eGPU using `llama-cpp-rdna-boosts`. It’s a single-setup result, but a useful candidate for benchmarking hardware-specific gains without adopting an entirely new inference stack. [Read](https://devnull.land/amd-specific-llama-cpp)

**3. Postgres query hints need an expiration review**
A PostgreSQL 19 walkthrough shows how plan advice fixes pathological queries—and how the same hint becomes dramatically slower after data distribution changes. Treat hints as monitored exceptions, use transaction-local settings, and revalidate them rather than making performance workarounds permanent. [Read](https://clickhouse.com/blog/pg-plan-advice-postgresql-19)

**4. Garage improves operations—but storage guarantees still matter**
Garage 2.6 adds a web administration UI and an official Helm repository, while the maintainers retire the 1.x branch. For backup architecture, note the bigger caveat: planned object locking will be best-effort, not a strict guarantee, because Garage lacks a consensus algorithm. [Read](https://garagehq.deuxfleurs.fr/blog/2026-11-webadmin-release/)

**5. Make execution plans inspectable data**
An AWS SDK generator refactor separates deciding what to do from executing it, enabling simpler tests, dry runs, and pre-execution checks. The practical migration technique: keep an explicit “old behavior” fallback while replacing tangled logic incrementally. [Read](https://jackkelly.name/blog/archives/2026/11/26/make_the_plan_a_value/)
