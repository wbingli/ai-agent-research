# Tech Digest — 2026-10-25

**1. AI-generated proofs move beyond toy programs**
Anthropic and Theorem report machine-checked no-crash proofs for 239 entry points across 123 libraries—not blanket guarantees, but bounded proofs for single-threaded RISC-V binaries. My takeaway: pilot verification on critical parsers and dependencies, while reviewing the specifications as carefully as the code. [Read](https://www.anthropic.com/research/formal-verification)

**2. A path-expansion helper can execute commands**
POSIX `wordexp()` performs shell-style expansion, including command substitution unless explicitly disabled; it is not merely a convenient way to expand `~/`. Audit configuration and filename-handling code for this API before allowing untrusted input through it. [Read](https://yossarian.net/til/post/posix-wordexp-3-is-dangerous/)

**3. More build threads can mean slower builds**
Wild 0.11.0 caps its default thread count at 32 to avoid Linux per-inode mutex contention, and enables WebAssembly linking by default without debug-info support. The useful performance lesson: benchmark filesystem behavior and concurrency limits, not just CPU utilization. [Read](https://github.com/wild-linker/wild/releases/tag/0.11.0)

**4. Python type checking learns your actual environment**
Astral’s experimental uv–ty integration checks scripts against their own declared dependencies and provides `uv check` with a lockfile-pinned type checker. This could reduce local-versus-CI drift; automatic editor environment setup remains opt-in because installing dependencies can execute third-party code. [Read](https://astral.sh/blog/uv-ty-integration)

**5. Practical computer vision on a tiny microcontroller**
A SIMD-optimized FAST feature detector runs roughly twice as fast as its reference implementation on the ESP32-S3, processing a 320×240 frame in about 6 ms. The implementation shows how alignment and signed-byte handling—not a bigger processor—can unlock cheaper edge-vision workloads. [Read](https://shraiwi.com/blog/simd-fast-esp32s3/)
