# Tech Digest — 2026-10-15

**1. Targeted ads become a zero-click spyware channel**
Researchers documented Candiru spyware infections at Al Jazeera delivered through targeted ads—no click required. For ad-platform teams, the takeaway is to treat third-party creative execution and vendor access as security boundaries, not just advertising plumbing. [Read](https://citizenlab.ca/research/how-discover-tech-turned-targeted-ads-into-a-pipeline-for-spyware/)

**2. Muse Spark Open brings another heavyweight self-hosting option**
Meta released an open-weight multimodal model with 816B total parameters, 42B active, and a million-token context, with support across major inference engines. It expands options for private coding and agent workloads, though deployment still requires substantial memory capacity. [Read](https://research.meta.ai/blog/muse-spark-open)

**3. AVIF still wins many practical image-delivery comparisons**
Jake Archibald’s benchmarks generally favor AVIF over JPEG XL for lossy web images, including screenshots and transparency; encoder choice and image content still matter. For media pipelines, benchmark representative assets rather than assuming the newer format lowers bandwidth or decode costs. [Read](https://jakearchibald.com/2026/jpeg-xl-vs-avif/)

**4. Rust 1.99.1 fixes an FFI correctness bug**
The patch restores correct zero-extension for x86_64 boolean returns across FFI, alongside fixes for missing `wcslen` symbols and macOS linker loading. Teams mixing Rust with other languages should prioritize testing this update: the FFI issue affects correctness, not merely build convenience. [Read](https://blog.rust-lang.org/2026/10/15/Rust-1.99.1/)

**5. Encrypted relays without trusting the relay operator**
Spritely’s upcoming Goblins release adds end-to-end encrypted, federated relays using the Noise protocol framework. The design is worth studying for peer-to-peer systems that must traverse restrictive networks without letting relay operators read or tamper with messages. [Read](https://spritely.institute/news/end-to-end-encrypted-relays-for-ocapn.html)
