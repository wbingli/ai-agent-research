# Tech Digest — 2026-10-30

**1. Claude Code extension compromise targets developer machines**
Phorion reports that Claude Code extension versions 2.1.312 and 2.1.313 distributed through Cursor’s marketplace contained an SSH backdoor and persistence mechanisms. Audit affected installations and involve incident response; a macOS implementation bug can block inbound SSH without preventing persistence. [Read](https://phorion.io/blog/offical-claude-code-vsx-compromise/)

**2. Google explores “sleep” for continual LLM learning**
Google’s research alternates active interaction with offline consolidation, updating pre-allocated expert memory using self-generated examples. It offers a research direction for retaining knowledge beyond a context window while mitigating forgetting—not a shipped, self-rewriting agent. [Read](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/)

**3. Idle HTTP/2 connections hide meaningful memory costs**
A Go 1.28 development-build benchmark saved roughly 85–93 MiB of resident memory across 5,000 idle connections by letting connection-serving goroutines exit until needed. These are single-machine, idle-workload results—not production guarantees—but a useful reason to benchmark connection-heavy services beyond heap usage. [Read](https://abdolirad.me/articles/go-1-28-http2-parking-memory/)

**4. Tangled separates global reads from code hosting**
Tangled’s forge moves from a single-server Go/SQLite application to an edge frontend and globally deployed, in-memory Rust indexers, while allowing selective self-hosting. The architecture is worth studying for separating read latency from hosting ownership and collaboration. [Read](https://tangled.org/blog/forge/)

**5. Firefox tackles the gap between patch publication and deployment**
Mozilla describes how AI-assisted attackers can reverse-engineer fixes before users update, and proposes staggering classes of fixes so their exposure windows do not overlap. The lesson: patch sequencing can complement sandboxing by denying attackers the complete exploit chain. [Read](https://blog.mozilla.org/en/firefox/privacy-security/defending-patch-gap/)
