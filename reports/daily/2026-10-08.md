# Tech Digest — 2026-10-08

**1. Fix message-bus overload before adding servers**
Jane Street replaced linear message-recovery scans with topic-partition indexes and ordered merging, reporting 30% lower CPU usage in some staging scenarios using real-world workloads. The useful lesson: benchmark slow-consumer recovery, not just steady-state throughput. [Read](https://blog.janestreet.com/scaling-and-benchmarking-a-critical-message-bus/) citeturn0view1

**2. Certificate renewals need a shorter clock**
Let’s Encrypt will default to 64-day certificates on February 10, 2027, with staging switching October 14, 2026. Audit hard-coded renewal schedules, enable ACME Renewal Info where supported, and test deployment/reload automation before the change. [Read](https://letsencrypt.org/2026/10/07/64-day-certs.html) citeturn0view2

**3. On-device speech recognition in 16.9 MB**
Cactus’s Whistle runs on CPUs, transcribes seven languages, and handles clips up to 30 seconds without sending audio to a server. It’s worth evaluating for private, offline voice interfaces—its published accuracy comparisons show trade-offs, not a universal win over Whisper. [Read](https://cactuscompute.com/blog/whistle) citeturn0view0

**4. Keep the physical network simple**
Hetzner explains why it puts firewalls and virtual networking on VM hosts while the physical network supplies IP connectivity. The architecture trades greater software ownership for flexibility and a smaller failure blast radius—a useful infrastructure design case study. [Read](https://www.hetzner.com/blog/the-hetzner-cloud-network-stack-history-and-technical-overview/) citeturn0view3

**5. A lakehouse built around SQL and Parquet**
DuckLake stores metadata in a SQL catalog and data in Parquet, with a DuckDB extension for ordinary SQL reads and writes. For analytics-platform teams, it offers a concrete alternative to evaluate when choosing how to manage lakehouse metadata. [Read](https://github.com/duckdb/ducklake) citeturn0view4
