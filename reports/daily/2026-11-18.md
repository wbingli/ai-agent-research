# Tech Digest — 2026-11-18

**1. Critical NGINX flaws put HTTP/2 endpoints at risk**
Two newly disclosed vulnerabilities can enable unauthenticated remote code execution in affected HTTP/2 configurations, with one demonstrated against ordinary static-file serving. Prioritize exposed deployments for security updates: secure application code does not protect a vulnerable proxy. [Read](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities)

**2. Gemini 4 Neon targets long-running coding agents**
Google’s new model offers a million-token context at $3 per million input tokens and $15 per million output tokens, emphasizing tool-heavy workflows and context compaction. My takeaway: evaluate it against your own agent completion rates and total task costs—not just leaderboard scores. [Read](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)

**3. Google open-sources faster, safer build caching**
ABFS combines lazy-loaded Git workspaces with shared, content-addressed build results; it verifies recorded file reads before reusing cached outputs, catching hidden dependency changes. A useful architecture for reducing cold-start overhead without trusting incomplete build graphs. [Read](https://developers.googleblog.com/en/accelerating-development-for-massive-git-repositories/)

**4. Nearly 58,000 integration tests in under three minutes**
Close replaced fixed test partitions with a shared work queue, overlapping setup and collecting only each worker’s assigned tests. Interruption-tolerant spot workers added parallelism at roughly the previous cost—a concrete CI design worth studying, though its main branch stays on-demand. [Read](https://making.close.com/posts/faster-ci-with-orchestrated-pytest-workers/)

**5. PyPI tightens uploads against parser discrepancies**
PyPI is rejecting problematic archive formats and ZIP comments to reduce cases where scanners and installers interpret the same package differently—even when hashes match. Consumers need no changes; maintainers encountering upload failures should check Python support and build-backend standards compliance. [Read](https://blog.pypi.org/posts/2026-11-18-stricter-checks-for-uploaded-sdists/)
