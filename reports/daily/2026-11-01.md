# Tech Digest — 2026-11-01

**1. ParticleDB’s ACID claims fail basic correctness tests**
Jepsen found data loss and transaction anomalies even on a single node, often without injected failures; Orkes says a newer release fixes all reported issues, but Jepsen has not verified it. The takeaway: require reproducible correctness tests—not compatibility claims or throughput benchmarks—before trusting a new database. [Read](https://jepsen.io/analyses/particledb-1.1.4)

**2. AI finds PostgreSQL bugs faster than humans can fix them**
PostgreSQL committer Robert Haas attributes version 19’s delay to an influx of LLM-discovered bugs and the human review burden of fixing them. Budget for triage and patch verification alongside AI coding gains: finding more defects can initially slow delivery. [Read](https://rhaas.blogspot.com/2026/10/postgres-19-is-late-and-its-ais-fault.html)

**3. Faster agents need better tools, not just faster models**
A practical optimization guide separates inference latency from shell startup, tool execution, polling, and sandbox overhead. Profile complete task traces and tune reasoning budgets before paying for faster inference; inefficient tool workflows may be the bigger bottleneck. [Read](https://martinalderson.com/posts/making-agents-fast/)

**4. Nibnib trades expensive encoding for tiny, fast decoding**
This experimental image format uses delta palettes to decode two pixels from each byte, targeting constrained microcontrollers. It’s a useful media-engineering example of shifting work toward encoding when playback resources are scarce—not a general-purpose video codec. [Read](https://github.com/raphlinus/nibnib)

**5. Better fuzzing starts with sanitizer configuration**
A resurfaced 2025 AFL++ guide shows how sanitizer defaults and incomplete state resets can hide bugs, even in already-fuzzed C/C++ code. Its checklist is worth applying to parsers and native media components before simply throwing more compute at fuzzing. [Read](https://nullprogram.com/blog/2025/02/05/)
